# V3失敗記録: 黒板を読ませたら黙る会議

## 何が起きたか

Llama 3.1 8B + Groqの4専門Agentへ、現在観測 `v/x/a` と前ラウンド黒板 `o/p/e` を同時に渡した。

最初に「黒板は古いので無視せよ」と明記した最小promptでは、合成ケースの `FIRE / LEFT / RIGHT / targetなしRIGHT / ammoなしWAIT` をそれぞれ正しく分類できた。

次に、黒板を本当に協調へ使うため、次の一文へ変えた。

> p,e,o are previous-round memory: use them for continuity, but never contradict current v,x,a.

するとRIGHT、targetなしRIGHT、WAITは通ったが、FIREケースとLEFTケースでは4人全員が0を返した。黒板の内容は初回値 `o=-1 p=0000 e=W` であり、現在観測と競合する具体的な提案すらなかった。

## 暫定解釈

8Bモデルには「現在値で厳密な二値条件を評価する」と「古い集団記憶を補助的に読む」を同時に要求するだけで、注意が分散する場合がある。情報量は数文字でも、命令の役割が増えること自体が効いているらしい。

## V3での扱い

- 黒板の生成、伝送、ログ保存は実装したまま残す
- 最初のlive baselineでは `Ignore p,e,o` と明記する
- つまり黒板は全Agentのcontextへ注入されるが、まだ運動判断には使わせない
- V3.1で、強いmodel、役別の黒板、遅延埋め込み、二段階判定を比較する

失敗を消して「最初から黒板不要だった」ことにはしない。この数文字で会議が黙ったこと自体が、複数LLM制御で測るべき現象である。
